# Socket 收發與壅塞處理

`TikTok.js` 的聊天、廣告、觀眾更新與心跳統一由 `SocketTransport.mjs` 發送。
通訊格式維持 UTF-8 JSON，每筆以換行結尾，不需修改既有接收端協定。

## 預設限制

- Node.js 待送佇列：最多 200 筆、合計 1 MiB；容量不足時淘汰最舊資料。
- 待送訊息有效期限：30 秒，在入列及發送前移除過期資料。
- 待送觀眾更新、心跳：同類型只保留最新一筆。
- 單筆 JSON：最多 256 KiB，接收端遇到超大資料會關閉連線。
- `write(false)`：該筆已由 Node.js 接受，後續訊息等待 `drain`，不重送該筆。
- 連線建立或等待 `drain` 超過 15 秒：關閉並重新連線。
- 重連間隔：15 秒；連續失敗超過 10 次後，每次增加 5 秒，最多 5 分鐘。
- 關閉：最多等待 2 秒，避免程式結束時卡住。
- Python 接收佇列：最多 200 筆，滿時淘汰最舊資料，不阻塞接收執行緒。
- Python 每次畫面更新：最多處理 20 筆，或在約 4ms 後停止取下一筆。
  單筆處理無法中途打斷，因此耗時的單筆工作仍可能超過此預算。

這些限制優先維持直播訊息的即時性。大量壅塞、超時或斷線時，可能捨棄訊息，
不是無損訊息儲存。尚未交給 Socket 的佇列資料會留待重連；已交给 TCP 的資料
沒有應用層 ACK，無法確認對方是否已處理，因此不會自動重送，以免重複顯示。

Node.js `[Socket]` 日誌每 10 秒最多回報一次佇列筆數、位元組、淘汰數與重連數。
淘汰數包含被更新狀態取代的資料。Python 佇列滿載日誌同樣節流。

## 驗證

```sh
node --test Test/socket_transport.test.mjs
node --check TikTok.js
python -B -m unittest discover -s Test -p socket_receiver_test.py
```

測試不啟動直播服務，不需登入平台。涵蓋分包／黏包、UTF-8 跨封包、格式錯誤、
訊息上限、背壓、過期資料、斷線補發、連線與關閉逾時，以及本機 TCP 慢速接收。

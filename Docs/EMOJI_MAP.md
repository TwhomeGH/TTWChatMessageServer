# 表情映射管理與熱載入

登入後開啟 `/emoji`，可搜尋、增加、編輯（包含重新命名）、刪除代碼，並預覽圖片。
主控台、剪輯分析與剪輯紀錄頁已加入入口。使用現有登入 cookie，未登入的 API 請求回傳 401。

`emoji_map.json` 格式仍是「完整代碼 → 圖片 HTTP(S) 網址」：

```json
{
  "[laughcry]": "https://cdn.jsdelivr.net/gh/twitter/twemoji@14.0.2/assets/72x72/1f602.png"
}
```

方括號等符號以普通文字匹配，代碼區分大小寫；重疊代碼優先匹配較長者。
替換不會再次處理剛插入的圖片網址。管理頁的縮圖改由伺服器端快取路由 `/emoji/image?code=…` 供應：
首次向來源抓取後存於 `cache/emoji-images/`，之後由本機供應並附長效快取標頭，避免每次開頁都重抓外部圖片。
路由只接受映射表中既有的代碼，不接受任意網址。預覽尚未儲存的新網址、以及聊天顯示端（疊加層）仍各自直接取得圖片。

聊天程序啟動後每秒重新檢查對應檔，網頁儲存或手動修改檔案皆會對後續新訊息生效，
已送出訊息不回溯更新。若 JSON 或欄位格式錯誤，保留最後有效版本，修正後自動恢復。
網頁按「重新載入」取得檔案最新狀態；不會自動覆寫正在編輯的表單。

儲存使用暫存檔替換原檔，並檢查版本指紋；兩個分頁先後修改時，過期的一方收到衝突提示，
須重新載入再修改。外部編輯器在寫入瞬間仍可能與儲存衝突，請避免同時手動寫檔與網頁儲存。
改名不能蓋掉既有代碼；圖片網址只接受不含帳密的 HTTP(S) URL。

首次安裝此功能需重啟 Server.js 與聊天子程序，使新程式載入；之後調整映射不用重啟。
新增的管理頁需建置 CSS，`npm start` 的指紋檢查會自動處理。

驗證指令：`node --test Test/emoji_store.test.cjs`。

# 留言統計與自動剪輯改進

Userscript 轉接格式見 [/chat 入口與參數文件](CHAT_API.md)；平台與接收管道的分類見 [來源說明](USERSCRIPT_SOURCES.md)。未知來源仍參與熱度，明確標記 `isTest: true` 的測試資料只顯示及記錄，不參與熱度。

## 資料與 keyword 頁面

- 每則留言只統計一次，翻譯不另加次數；ID 去重依平台區分。
- 統計保留內容、次數、首次／最後已知時間、平台及每種留言最近 5 筆紀錄。
- 最近紀錄有使用者、訊息 ID、平台時間、接收時間與時間來源。
- TikTok／YouTube 使用可取得的原始時間；Twitch 的目前聊天 SDK 事件未提供
  發送時間，使用處理回呼入口的接收時間，避免把查詢頭像的耗時算入事件時間。
- 舊檔案可直接載入，保留次數；未保存的歷史時間與留言明細無法還原。
- keyword 顯示 Top 10、可搜尋／排序／分頁的全部留言，以及最多 200 筆最近紀錄。
  這是完整留言統計，沒有把句子拆成詞。
- 主程序與子程序沿用同一累計快照；啟動子程序前保存基準，合併快照不重複相加。

## 剪輯判斷

- 所有平台聊天均可觸發，Twitch 僅是剪輯畫面入口。各平台用自己的聊天／觀眾基準計算分數，取通過最低留言量與發言人數的平台最高分。安靜平台不稀釋热度；不把不同平台的觀眾當作同一人去重。
- 建議設定：30 秒窗口、每 5 秒評估、持續約 10 秒；每平台最少 6 筆、3 位不同發言人；分散在多平台且各自未達此門檻時不觸發。
- 每人每窗口最多計入 3 筆。多人相同留言可以計入，不再全域按文字去重。
- 基準排除當前窗口；先暖機 3 分鐘，資料過期或 Socket 斷線會重新暖機。
- 除加權分數外，聊天速率至少需要達基準下限的 1.5 倍；觀眾倍率最多採計 2 倍。
- 暫存 ID 最多 10,000 筆／30 分鐘；舊聊天不納入，ID 及發言人限制依平台區分。
- `AUTO_CLIP_MODE=shadow` 是預設值：只記錄，不向 Twitch 發送剪輯請求。
  Config 可改成 `live`，儲存後重新啟動子程序生效。`AUTO_CLIP_ENABLED=1` 仍為必要條件。
- 影子觸發、正式觸發、建立中、成功及失敗分開統計。成功需查到可用剪輯。
  請求逾時或未確認可用時不立即重送，保留冷卻以免重複建立。
- 自動剪輯不再要求延後建立；手動剪輯維持原設定。

## 圖表與時間核對

觸發點旁顯示計入的留言數、發言人數及一則短文；最多標示最近 8 個觸發點，
碰到標籤重疊會省略部分摘要，仍可用點擊／下拉選單選取所有保留的事件。

展開區顯示該點的統計窗口、分數、門檻與計入留言。觸發時固定保存快照，
每個事件最多保存 200 則、每則文字最多 1,000 字元；截斷會標示在筆數說明。
這份清單是「被計入熱度的留言」，不是全部收到的原始聊天。
舊圖表紀錄未保存訊息，會顯示無法補回。

另保存熱度開始、觀測峰值、觸發、請求與完成時間。如果 Twitch 提供剪輯的
VOD 位移，且能確認 VOD 屬於同一直播，才計算片段是否涵蓋觀測峰值；
沒有足夠資料就標示尚未核對，不能據此保證已剪到遊戲／畫面的精彩瞬間。
觀眾反應與直播畫面仍有延遲，需要先用影子模式對照實際直播校準。

## 本次本機設定

將原本的 5 分鐘窗口／1.5 分鐘持續確認，調成 0.5／0.167 分鐘；
觀眾與聊天權重調成 0.2／0.8，訊息基準下限調為每分鐘 2 筆，模式設為 shadow。
尚未啟動正式剪輯，沒有發送 Twitch 測試請求。

## 驗證

```sh
node --test Test/message_stats.test.mjs Test/autoclip_v2.test.mjs Test/tiktok_chat_guard.test.mjs Test/socket_transport.test.mjs
node --check TikTok.js
node --check Server.js
```

`node Test/keyword_preview.mjs` 提供本機 18765 埠的合成資料 UI，供檢查
keyword、autoclip 與 config；不讀取真實留言、不啟動直播、不保存設定。

## 跨平台時間校準

可在 .env 設定 AUTO_CLIP_PLATFORM_DELAY_MS={"TikTok":5000,"Youtube":10000}，單位毫秒，正值代表該平台反應相對 Twitch 畫面落後，從事件時間扣除。預設全部為 0，不猜測延遲；需要用實際直播核對。校準後超出窗口的留言不納入即時熱度。圖表明細保存校準前時間及各平台分數／採計貢獻。

觀眾人數只使用可取得且未過期的平台資料；例如沒有 Kick 人數時，Kick 聊天仍可獨立觸發。Twitch 剪輯入口離線或資料過期時維持暫停、重新暖機。
